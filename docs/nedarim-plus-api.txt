

==================== #1  תיעוד API ====================
> תיעוד טכני זה מיועד למפתחים שרוצים ליצור משימות וליצור אינטראקציה עם נדרים פלוס.
> לכל שאלה או בעיה ניתן לפנות לעזרה בכתובת office@nedar.im


==================== #2  מבוא ====================
- כל שיחות הממשק הן בפרוטוקול https.
- התאריכים הם בפורמט dd/mm/yyyy.
- בכל פניה יש להוסיף פרמטר מזהה מוסד, שם הפרמטר לפעמים שונה עקב סוגי API שונים
- בכל פניה יש להוסיף פרמטר אימות - מפתח API שיוצרים עצמאית במסך הגדרות > API > מפתחות API (ApiPassword, מתחיל ב-npk_).
- סיסמת האימות לדף התשלום (ApiValid) מוצגת אף היא בראש מסך מפתחות API.
- פרמטר חובה מסומן בכוכבית

==================== #6  מערכת Callback / Webhook ====================

### איך זה עובד?
- באמצעות מערכת זו, תוכלו לקבל עדכון לשרתים שלכם לאחר כל עסקת אשראי ו/או הקמת הוראת קבע.
- ההגדרה עצמאית מהממשק: בתפריט הגדרות > API > Webhook מזינים כתובת https בשדה "עדכוני עסקאות" ו/או בשדה "הקמת הוראת קבע" ולוחצים שמירה. מחיקת הכתובת מכבה את השליחה.
- העדכון נשלח על עסקאות מוצלחות באשראי, בביט ובהעברה בקליק - לא על הוראות קבע בנקאיות. עסקה שנכשלה אינה נשלחת כאן (לסירובים יש Webhook נפרד).
- תשלום באשראי או הקמת הוראת קבע מהאייפרם נשלחים לכאן גם כשבעסקה עצמה הוגדר CallBack - שני העדכונים יוצאים, בסדר שאינו מובטח (השדה DebitIframe = 1 מסמן עסקת אייפרם). בביט ובהעברה בקליק עם CallBack ברמת העסקה - רק ה-CallBack נשלח, לא לכאן.
- המידע נשלח ב - POST
- המידע נשלח כ - application/json
- במידה וקרתה תקלה במהלך שידור המידע, תקבלו על כך התראה במייל.
- המערכת לא תנסה לשדר יותר מפעם אחת.
- מעת לעת המערכת מתעדכנת ונוספים פרמטרים חדשים.
- שמות הפרמטרים הקיימים לא ישתנו.
- סדר הפרמטרים עלול להשתנות מעת לעת.

### אז איך זה עובד?
- הלקוח נכנס לדף תשלום שלכם הכולל בתוכו אלמנט iframe<br>הדף נותן פקודה לאייפרם לטעון את הקישור הזה > https://www.matara.pro/nedarimplus/iframe/
- לאחר טעינה של האייפרם, הדף שלכם "שואל" את האייפרם מה הגובה שלו (height)<br>ניתן בכל שינוי גודל החלון לבדוק מה גובה האייפרם, על מנת לוודא שהאתר שלכם רספונסיבי.
- האייפרם שולח לכם את הגובה, שאותו אתם מגדירים מיד ב Style של האייפרם.
- הלקוח ממלא את הפרטים שלו ואת פרטי האשראי, ולוחץ על בצע תשלום.
- הדף שלכם שולח לאייפרם את כל המידע על העסקה (שם, כתובת, טלפון וכו) שהלקוח הזין בדף.

- בדף עצמו: כשמתקבל TransactionResponse עם Status: OK, שאלו את השרת שלכם (לא את נדרים) האם האישור התקבל, ורק אז שחררו את הגולש לשלב הבא.

### אימות מקור העדכון
> בלי אימות, כל מי שמנחש את כתובת ה-Callback שלכם יכול לשלוח POST עם אותם שדות בדיוק. שני מנגנונים, ומומלץ להשתמש בשניהם: חתימת HMAC-SHA256 על כל עדכון ורשימת כתובות ה-IP שמהן נשלחים העדכונים. הפורמט, קוד האימות ב-Node / PHP / C#, החלפת מפתח וההתראות המומלצות - הכל בכרטיס "חתימת HMAC על עדכוני Webhook" שבמדור Webhook. וגם אחרי האימות: הצלבה מול ה-Param הייחודי ומול הסכום.

### מה עושים אם עדכון לא הגיע
- העדכון נשלח פעם אחת בלבד, מהתור שלנו, שניות ספורות אחרי העסקה (לא בתוך אותה בקשה). אם היתה תקלה בשליחה (למשל השרת שלכם לא היה זמין) תישלח על כך התראה במייל - לכתובת CallBackMailError אם נשלחה, אחרת למנהלי המוסד שמוגדרים לקבלת מיילים.

==================== #160  העברה בקליק ====================
> העברה בקליק היא תשלום ישיר מחשבון הבנק של התורם (בנקאות פתוחה): התורם מאשר את ההעברה באפליקציית הבנק שלו, והעסקה נרשמת בנדרים פלוס כעסקת אשראי לכל דבר. הפעולה זמינה למוסדות שהצטרפו לשירות העברה בקליק. האייפרם מיועד לאשראי בלבד - להעברה בקליק מחברים את הלחצן באתר שלכם דרך ה-API הזה, ואפשר להציג אותו באותו עמוד לצד האייפרם.

### איך זה עובד?
- התורם ממלא בדף שלכם את פרטיו, את הסכום ואת פרטי חשבון הבנק שממנו הוא משלם (בנק, סניף, חשבון ומספר זהות של בעל החשבון).
- השרת שלכם פונה לנדרים פלוס (CreateTransaction) ומקבל בחזרה קישור קצר ומזהה בקשה (PreTransactionId).
- מפנים את התורם לקישור (או שולחים לו אותו ב-SMS עם SendSms=1). הקישור מעביר אותו לאפליקציית הבנק שלו, שם הוא מזדהה ומאשר את ההעברה.
- בסיום התהליך בבנק התורם חוזר לכתובת UrlSuccess או UrlFailure ששלחתם, ונדרים פלוס רושמת את העסקה.
- אם הזנתם CallBack - תקבלו עדכון לשרת שלכם עם השלמת העסקה. בנוסף אפשר לדגום את סטטוס הבקשה בפעולה CheckTransaction (למטה).
- להצגת אישור תשלום על המסך שלכם: שולחים בהקמה מזהה ייחודי בפרמטר Param2, ולאחר ההקמה דוגמים את השרת שלכם עד שהעסקה עם המזהה הזה התקבלה בקאלבק (או דוגמים את CheckTransaction).
> מגבלות השירות: תשלום בשקלים בלבד, בתשלום אחד, ומחשבון בנק פרטי בלבד (מספר זהות של בעל החשבון; חשבון עסקי עם ח"פ אינו נתמך בשלב זה). חשבון הבנק המקבל של המוסד לא יכול לשמש כחשבון המשלם.

==================== #161  מטבע דיגיטלי (קריפטו) ====================
> תשלום במטבע דיגיטלי: התורם משלם בקריפטו בדף התשלום המאובטח של שרות הסליקה, והמוסד מקבל את התרומה בשקלים. העסקה נרשמת בנדרים פלוס עם אמצעי תשלום "מטבע דיגיטלי". הפעולה זמינה למוסדות שחיברו את השירות במסך הגדרות > שירותים מחוברים > "מטבעות דיגיטליים". האייפרם מיועד לאשראי בלבד - את לחצן הקריפטו מחברים באתר שלכם דרך ה-API הזה.

### איך זה עובד?
- השרת שלכם פונה לנדרים פלוס (CreateTransaction) עם פרטי התורם והסכום, ומקבל בחזרה קישור לדף התשלום של שרות הקריפטו ומזהה בקשה (PreTransactionId).

==================== #199  חתימת HMAC על עדכוני Webhook ====================
> עדכון Webhook הוא POST לשרת שלכם - ובלי אימות, כל מי שמנחש את הכתובת יכול לשלוח POST עם אותם שדות בדיוק ולגרום למשל להפקת קבלה על תרומה שלא הייתה. חתימת HMAC-SHA256 היא הוכחה קריפטוגרפית שהעדכון נוצר אצלנו ולא שונה בדרך: מפתח סודי משותף למוסד ולנו, וכל עדכון יוצא עם חתימה שמחושבת מהמפתח ומגוף ההודעה. השרת שלכם מחשב את אותה חתימה ומשווה. לא תלוי בכתובות IP, ולא נשבר כשכתובת משתנה.

### איך זה עובד
- מפעילים במסך הגדרות > API > Webhook > "חתימת HMAC": המפתח מוגרל בדפדפן, מעתיקים אותו לשרת שלכם, ורק אז לוחצים "הפעלה". המפתח מוצג פעם אחת; אחרי ההפעלה רואים רק את 4 התווים האחרונים. אפשר גם דרך ה-API - פעולת "הגדרת מפתח חתימת Webhook".
- מרגע ההפעלה <b>כל</b> עדכון שנשלח למוסד יוצא עם שתי כותרות HTTP: עסקאות, הקמת הוראת קבע, סירובים, טפסים, ביט, העברה בקליק, מטבע דיגיטלי, וגם "שליחת בדיקה" מהמסך:
- <code>X-Nedarim-Timestamp</code> - שניות מאז 1970 (UTC) ברגע השליחה.<br><code>X-Nedarim-Signature</code> - <code>v1=</code> ואחריו HMAC-SHA256 בהקסה קטנה (64 תווים) על המחרוזת <code>timestamp + "." + body</code>, כשהמפתח הוא ה-Secret כמחרוזת UTF-8.
- <b>ה-body הוא הבייטים הגולמיים של הבקשה</b> בדיוק כפי שהתקבלו - לא אחרי parse ו-serialize מחדש. זו הטעות הנפוצה: כל שינוי ברווחים או בסדר השדות משנה את החתימה.
